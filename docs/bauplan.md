# Baupläne + /vorlagen

Lead-magnet PDFs, their pages and the `/vorlagen` hub, read on demand when touching `/bauplan/*`, `/vorlagen/*`, `content/bauplan/` or `src/lib/bauplan*`. Business context (codes, outreach, the load-bearing Agentur PDF name) → [Knowledge/INDEX.md](../../Knowledge/INDEX.md). Always-needed rules → [../CLAUDE.md](../CLAUDE.md).

## /vorlagen hub

- **`/vorlagen` hub (out of the top nav; the header button leads there):** cards (Prozess-Check first), copy + slugs in `src/lib/vorlagen.ts`, each asset keeps its own gate: the Haus PDF downloads directly (`public/vorlagen/vrelo-ki-betriebssystem.pdf`, a copy of `Clients/_kit/fahrplan/vrelo-betriebssystem-haus-vorlage.pdf`: re-render there, then copy here) · Claude-Gehirn links to its ungated page · the two Baupläne get **public, indexable copies** at `/vorlagen/<slug>` with full chrome, same components and copy as `/bauplan/<code>`. Their form posts a public token (`VORLAGE_TOKEN` in `src/lib/bauplan.ts`) instead of the secret code, so the code never reaches public HTML; only the server action accepts the token (`bauplanFormVariant`), `/bauplan/<token>` stays 404. Default `src` = `vorlagen` (internal mail „Quelle: vorlagen“), `?src=` overrides it. No ClosingCta (gifts; the Baupläne carry their own offer).

## Bauplan für Agenturen (`/bauplan/[code]`)

- **Bauplan für Agenturen:** unlisted page `/bauplan/[code]` (`src/app/bauplan/[code]/page.tsx`); the valid code is the env `BAUPLAN_CODE` (`src/lib/bauplan.ts`), a wrong code gives 404. noindex, not in the sitemap, focus chrome via `focusPrefixes` in `src/lib/nav.ts`. The form (`BauplanPdfForm` → server action `submitBauplanRequest` → `src/lib/bauplanEmail.ts`) mails the PDF to the requester via Resend and an internal mail to Ajdin with `Quelle: <src>`; one link per agency: `/bauplan/<code>?src=ag<nn>` (CSV id). **`BAUPLAN_CODE` must be set in Vercel Production before the push to `main`**, else the page 404s for everyone; Production also needs `RESEND_API_KEY`, `CONTACT_FROM` and `CONTACT_TO` (the form fails without them). PDF: `npm run bauplan:pdf` renders `content/bauplan/agentur-bauplan.html` to `public/bauplan/agentur-bauplan-<hash>.pdf`; after a re-render update `BAUPLAN_PDF_PATH` in `bauplanEmail.ts` (a test asserts the file exists). **Rotation = change `BAUPLAN_CODE` and redeploy** (Vercel env changes only reach new deployments; old links 404, and the form action also rejects a stale code); the PDF file name stays by design. PDF attached from disk; `outputFileTracingIncludes` ships `public/bauplan/*.pdf` with the function (mail body keeps the download link as fallback). **Review gate:** Ajdin reviews the rendered PDF before it is committed. Spec: `docs/superpowers/specs/2026-10-27-agentur-bauplan-design.md`.

## Bauplan für Elektrobetriebe

- **Bauplan für Elektrobetriebe:** free seven-page PDF lead magnet. **Pages 1 to 6 are a guideline, page 7 is the offer**: done-for-you with a deposit-back guarantee, „Erste Ergebnisse nach 2 Tagen“ as the only public timeline, button to `/kontakt?src=bauplan-elektro(-pdf)`; the same copy closes the landing page as section `#angebot` (`angebot` in `elektroBauplanPage.ts`, the PDF test checks page 7 against it word for word). ⚠ „Geld-zurück-Garantie“ is only true with 50/50 payment (final invoice after acceptance), never with full prepayment; the guard `src/lib/elektroBauplanTemplate.test.ts` pins that, plus the facts (no price or duration, no client names, interfaces only „wenn sie eine Schnittstelle haben“). Template `content/bauplan/elektro-bauplan.html` (pure ASCII entities, decoded by `src/lib/bauplanTemplateText.ts`, shared with the Agentur guard). `npm run bauplan:elektro` renders to `.preview/elektro-bauplan.pdf` and fails unless it is exactly 7 pages; `-- --publish` renders nothing and copies the reviewed file to `Knowledge/Offers/Elektro-Bauplan-Vrelo.pdf` and to `public/bauplan/elektro-bauplan-<hash>.pdf` (older Elektro copies removed); then set `ELEKTRO_BAUPLAN_PDF_PATH` in `src/lib/bauplanEmail.ts` to the printed name (a test asserts the file exists). ⚠️ A PDF open in a viewer locks the file (EBUSY): close it before re-rendering. Page 1 is `min-height`, so an overflow becomes an extra page the gate catches. **Landing page:** same route `/bauplan/[code]`, second code in env **`BAUPLAN_CODE_ELEKTRO`** (`bauplanVariant()` in `src/lib/bauplan.ts` resolves a code to `agentur` | `elektro`; equal codes serve the Agentur page). Copy `src/lib/elektroBauplanPage.ts` (frozen, Ajdin approved; change only with his OK), component `ElektroBauplanPage`, the form reuses `BauplanPdfForm` with `copy`. Mails per variant in `bauplanEmail.ts`: reader „Dein Bauplan für Elektrobetriebe“ with `Vrelo-Bauplan-Elektrobetriebe.pdf`, internal „Elektro-Bauplan angefordert: <email>“ with `Bauplan:` and `Quelle:` lines. One link per Betrieb: `/bauplan/<code>?src=el<nn>` (lead-list id). **`BAUPLAN_CODE_ELEKTRO` must be set in Vercel Production before the push**, else the page 404s. Spec + plan: `docs/superpowers/{specs,plans}/2026-10-29-elektro-bauplan-{pdf,landing}*`; mockup `docs/design/elektro-bauplan/landing-mockup.html`.

## Bauplan-Reihe (`/vorlagen/<slug>-bauplan`)

- **Bauplan-Reihe (SHK was the pilot; all niches live):** one public, indexed, form-gated page per niche at `/vorlagen/<slug>-bauplan` (card on `/vorlagen`, in the sitemap; the form posts the public token `vorlage-shk`, mails the PDF, notification says `Bauplan: SHK-Betriebe` + `Quelle: vorlagen`, `?src=` overrides). **No coded `/bauplan/<code>` page for series niches.** Layer `src/lib/bauplanReihe/`: `shared.ts` (copy used word for word in every niche: self-check, level rule `levelFor` + `LEVELS`, `wochenplan`, `deckblatt`, `formular`, `abschluss` with heading „Wenn du Fragen hast, melde dich. Kostenlos.“, `abschlussHref`), one data file per niche (`shk.ts`, registered in `index.ts` `reiheNischen`), `templateGuards.ts` + `templates.test.ts` (ASCII + entities, shared copy verbatim, headings, 8 pages, visible link targets, verified interfaces only, `knownTools` coverage, no station numbers, no prices/durations/names, KI disclosure). Template `content/bauplan/<slug>-bauplan.html` + shared `content/bauplan/reihe.css`; `content/bauplan/reihe.json` holds pages + `shareCopy` per slug. Page `ReiheBauplanPage` via `src/app/vorlagen/[slug]/page.tsx`; mail `MAIL.<slug>` is built from the niche data in `bauplanEmail.ts`; `BauplanVariant` + `VORLAGE_TOKEN` in `bauplan.ts`; `next.config.ts` traces `public/bauplan/*.pdf` for both routes. **Render:** `VRELO_HQ=C:/Users/ajdin/Vrelo npm run bauplan:reihe -- <slug>` -> `.preview/<slug>-bauplan.pdf` + page gate; `--publish` writes `public/bauplan/<slug>-bauplan-<sha8>.pdf`, deletes that slug's old hash (never the protected agentur/elektro PDFs) and copies to `Knowledge/Offers/<shareCopy>`; then put the printed `pdfPath` into the niche file. Warning: every republish changes the hash, so links in already-sent mails to the old file break (attachments stay fine). **New niche in four steps:** (1) research (prozess-landkarten section, owner OK) · (2) niche data file + register in `index.ts` + `reihe.json` entry · (3) template copied from the SHK one, guards green · (4) render/publish, owner review, then `BauplanVariant`, `VORLAGE_TOKEN`, `TITLE` and the `vorlageBauplaene` entry. Print copy for the Schmid meeting 2026-11-26: `Knowledge/Offers/SHK-Bauplan-Vrelo.pdf` (8 pages).
